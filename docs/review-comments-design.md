# 리뷰 댓글 설계

상태: Q1~Q14 및 최종 설계 승인 후 구현 완료.

## 확정된 범위

- 커뮤니티와 게임 상세의 리뷰 카드에서 같은 댓글 목록을 열고 작성한다. 홈·프로필 카드 확대는 이번 범위에서 제외한다.
- 댓글과 한 단계 답글을 지원한다. 답글 아래에 답글을 계속 중첩하지 않는다.
- 댓글과 답글 모두 좋아요 및 취소를 지원한다. 사용자별 댓글당 좋아요는 최대 한 개다.
- 읽기는 해당 리뷰의 공개 정책을 따른다. 공개 리뷰의 댓글은 비로그인도 읽을 수 있다.
- 작성과 좋아요는 로그인이 필요하다. 수정과 삭제는 해당 댓글 작성자 본인에게 허용한다.
- 텍스트 최대 1,000자이며 줄바꿈을 허용하고 공백만 있는 내용은 거부한다.
- 이미지와 스티커 첨부는 이번 범위에서 제외한다.
- 댓글 영역은 기본적으로 접혀 있고 리뷰 카드의 댓글 버튼으로 펼친다. 원댓글은 오래된 순으로 20개씩 더 보기로 조회한다.
- 답글은 원댓글 아래에서 별도로 펼치며 오래된 순으로 10개씩 조회한다.
- 원댓글 삭제 시 삭제된 자리와 기존 답글은 유지한다. 본문·작성자·좋아요를 숨기고 “삭제된 댓글입니다”를 표시하며 새 답글 작성을 막는다. 기존 답글 작성자는 본인 답글을 수정·삭제할 수 있다.
- 사용자가 리뷰를 삭제하면 기존 댓글·답글·댓글 좋아요를 함께 삭제한다. 같은 리뷰를 재작성해도 이전 댓글이 다시 나타나지 않는다.
- 관리자가 리뷰를 숨기면 댓글은 보존하지만 조회와 작성을 막는다.
- 스포일러 리뷰는 “내용 보기”를 누른 뒤 댓글 영역을 열 수 있다.
- 댓글과 답글 각각 작성 시 “스포일러 포함”을 설정할 수 있다.
- 리뷰 작성자의 댓글에는 “리뷰 작성자” 배지를 표시한다.
- 답글 입력 시 대상 닉네임을 표시한다. 알림 및 사용자 검색 멘션은 이번 범위에서 제외한다.

## 작성과 목록 갱신

- 댓글 개수는 삭제되지 않은 원댓글과 답글의 합계다.
- 삭제된 답글은 목록에서 제거한다. 삭제된 원댓글은 살아 있는 답글이 있을 때만 “삭제된 댓글입니다”로 남긴다.
- 본인 댓글 수정 시 기존 내용을 입력창에 표시하고 본문과 스포일러 여부를 변경할 수 있다. 저장과 취소를 제공한다.
- 수정 후에도 최초 작성 순서를 유지하며 “수정됨”을 표시한다.
- 삭제는 “댓글을 삭제할까요?” 확인 후 처리한다.
- 등록 요청 중에는 등록 버튼을 잠근다. 요청 실패 시 작성 내용을 유지한다.
- 인증 갱신도 실패하면 현재 브라우저 탭에 초안을 임시 보관하고 로그인으로 이동한다.
- 로그인 후 원래 리뷰의 댓글 영역으로 복귀해 초안을 복원한다. 복원된 글은 자동 등록하지 않으며 사용자가 다시 등록한다.
- 다른 사람의 새 댓글은 댓글 영역을 다시 열거나 “새로고침”을 눌렀을 때 반영한다.
- 본인이 작성한 댓글은 성공 직후 표시한다. 답글 작성에 성공하면 해당 답글 목록을 펼친다.

## 구현

- 공통 UI: `front/src/features/reviews/components/review-comments.tsx`.
- API: `/api/v1/reviews/{reviewId}/comments`. 조회·개수·단건 조회는 공개, 작성·수정·삭제·좋아요는 인증 필수다.
- 원댓글과 답글은 증가하는 ID 커서로 오래된 순서를 유지하며, 수정 시 위치는 바뀌지 않는다.
- 본인이 작성한 항목이 아직 조회한 페이지 밖에 있으면 “방금 작성한 댓글/답글” 영역에서 즉시 보여준다.
- 로그인 복귀 URL의 `commentReview`로 원래 리뷰를 별도 표시하므로 리뷰가 피드 다음 페이지로 이동해도 초안에 접근할 수 있다.
- 초안은 사용자·리뷰별로 현재 탭의 sessionStorage에 보관하고 등록 성공 또는 취소 시 제거한다.
- 댓글 변경 작업은 리뷰 행 잠금을 사용해 리뷰 삭제와 직렬화한다. 좋아요 PUT/DELETE는 반복 요청에도 한 개/0개 상태를 유지한다.
- 삭제 댓글은 본문을 비우고 공개 응답에서 작성자 정보를 제거한다. 사용자 리뷰 삭제 시 댓글 좋아요, 답글, 원댓글 순으로 정리한다.

## DB 적용

- 운영 DB는 `ddl-auto: validate`이므로 새 서버 배포 전에 [운영 적용 SQL](sql/review-comments.sql)을 한 번 실행해야 한다.
- SQL은 부모 댓글, 스포일러, 삭제·수정 여부 컬럼과 조회 인덱스를 추가한다. 이미 개발 환경의 자동 스키마 업데이트로 추가된 DB에는 그대로 재실행하지 않는다.
- 이 작업에서는 운영 DB에 SQL을 실행하지 않았다.

## 검증

- `ReviewCommentControllerTest`: 공개 조회/인증, 입력 제한, 답글 깊이, 소유권, 좋아요 중복 방지, 삭제 처리, 페이지 크기, 리뷰 삭제·복원 및 관리자 숨김을 검증한다.
- 기존 `ReviewServiceTest`, `ReviewLibraryLifecycleTest`, `CommunityReviewControllerTest`를 함께 실행해 53개 테스트가 통과했다.
- 답글과 답글 좋아요를 포함한 게임 삭제 시나리오를 추가한 `IgdbSyncTest`도 통과했다.
- 모의 API를 연결한 브라우저 검사에서 댓글 펼침, 답글, 좋아요, 스포일러, 수정·삭제, 작성 실패 시 입력 유지, 재로그인 초안 복원과 모바일 가로 넘침을 확인했다.
- 프론트 프로덕션 빌드와 새 댓글 코드 린트가 통과했다.
