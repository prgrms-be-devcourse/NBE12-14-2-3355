# 관리자 IGDB 동기화

관리자로 로그인한 뒤 상단 **게임 데이터 관리**(`/admin/igdb`)에서 실행합니다.
서버는 `POST /api/v1/admin/igdb-sync`에 202를 반환하고 백그라운드에서 실행하며,
`GET /api/v1/admin/igdb-sync`로 현재 상태를 제공합니다. 두 API 모두 ADMIN 전용입니다.
`local`, `prod` 모두 사용할 수 있으며 IGDB 환경변수가 필요합니다.

## 데이터 범위

- IGDB `first_release_date`가 0(1970-01-01T00:00:00Z) 이상, **작업 시작 시각** 이하인 게임만 저장합니다.
- 최초 전체 동기화는 IGDB 게임을 ID 오름차순으로 500개씩 읽어 기존 행을 갱신하거나 추가합니다.
- 이후에는 마지막 성공 기준에서 5분을 겹쳐 `updated_at` 변경분과 **새로 출시일이 도래한 게임**을 함께 조회합니다.
- 출시일 미상/1970년 이전/미래로 변경된 기존 게임은 리뷰, 댓글, 좋아요, 신고, 플레이 기록, 선호·대표 게임 연결까지 삭제합니다. 사용자 계정은 유지합니다.
- 범위에 해당하는 기존 게임은 DB ID, 사용자 기록, 집계값을 보존합니다. 장르·플랫폼·시리즈 연결은 최신 응답으로 교체합니다.
- 게임 설명 원문은 갱신하며 기존 한국어 번역은 유지합니다. 재번역은 별도 번역 기능으로 실행합니다.
- IGDB에서 완전히 삭제되어 응답에 더 이상 나오지 않는 게임을 찾아 지우는 기능은 포함하지 않습니다.
- 관련 리소스만 수정되고 게임의 `updated_at`이 바뀌지 않는 경우 증분 수집만으로 감지되지 않을 수 있습니다.

## 진행 상태와 재시작

`igdb_sync_state`에 커서, 실행자, 처리 건수와 성공 기준을 저장합니다. 현재 설정의 Hibernate `ddl-auto: update`로 테이블이 생성됩니다.
500개 단위 저장과 커서 갱신은 동일 트랜잭션이므로 실패한 페이지는 반영되지 않습니다.
실패 후 버튼을 누르면 기존 작업의 기준 시각과 커서부터 이어서 실행합니다. 완료 후 다시 누르면 그 사이의 변경분을 처리합니다.
전체 작업이 성공하기 전에는 마지막 성공 기준을 전진시키지 않습니다.
DB 행 잠금과 실행 ID로 중복 실행 및 이전 작업자의 늦은 저장을 막습니다.
강제 종료 시 마지막 처리부터 최대 10분 후 이어서 실행할 수 있습니다. 정상 실패는 즉시 재시도할 수 있습니다.
외부 요청은 30초 제한, 429/5xx는 최대 3회 재시도합니다. 외부 API 호출 중에는 DB 트랜잭션을 열지 않습니다.
이 앱 밖의 프로그램에서 같은 IGDB 자격증명을 쓰는 경우 요청 제한을 함께 고려해야 합니다.

기존 `--igdb.import.enabled=true` 옵션도 이 동기화를 시작합니다(local 전용). 평소에는 옵션을 끄고 관리자 버튼으로 실행하세요.
운영 적용 시 DB 백업 후 서버를 배포하고 관리자 화면에서 최초 전체 동기화를 시작하세요.
