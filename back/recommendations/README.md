# 연관 추천 수동 사전 계산

백엔드 서버 실행과 별도로 명령을 실행하며, 작업이 끝나면 종료한다. 일반 서버 시작만으로는 계산하지 않는다. 관리자 페이지와 자동 갱신은 후속 작업이다.

## 실행 준비

- Java 25, Docker MySQL과 1번 커밋에서 추가한 두 테이블이 필요하다.
- 명령은 `local` 프로필을 사용하되 스키마는 `validate`, SQL 초기화는 `never`로 실행한다. 테이블을 자동 생성하거나 초기 데이터를 실행하지 않는다.
- 접속 주소 기본값은 `application.yaml`의 local 설정이다. 현재 설정의 DB 이름은 `gamelog_retry`이므로, 실제 로컬 DB가 `gamelog`라면 아래처럼 연결 주소를 지정한다. 사용자·비밀번호는 기존 `DB_USERNAME`, `DB_PASSWORD` 환경변수를 사용하고 명령에 비밀번호를 직접 적지 않는다.

### 로컬 DB가 `gamelog`인 경우

Docker MySQL을 실행한 뒤, 저장소 루트의 터미널에서 다음 순서로 실행한다.

```bash
cd back
export SPRING_DATASOURCE_URL='jdbc:mysql://localhost:3306/gamelog?serverTimezone=UTC&characterEncoding=UTF-8'

# 같은 터미널에서 전체 최초 계산 실행
./gradlew recommendationPrecompute --args='--all --mode=INITIAL_LOAD'
```

- `export`는 현재 터미널 세션에 적용된다. 새 터미널에서는 다시 지정해야 한다.
- IntelliJ의 Spring Boot 또는 Gradle 실행 구성에 지정한 환경변수는 터미널 실행에 자동 적용되지 않는다.
- 시작 로그의 `Database JDBC URL`이 `jdbc:mysql://localhost:3306/gamelog?...`인지 확인한다.
- 이전 실행을 중단했더라도 위 명령은 전체 대상을 다시 계산한다. 이미 완료된 게임의 결과는 다시 교체하며, 중단 지점부터 이어서 실행하지 않는다.
- 100건마다 출력되는 진행 로그를 확인하고, 1,000건 처리 시점의 경과 시간으로 전체 소요 시간을 가늠한다. 공통 데이터 준비 시간만으로 전체 시간을 판단하지 않는다.

## 실행 명령

```bash
# 도움말: DB에 연결하지 않고 사용법 확인
./gradlew recommendationPrecompute --args='--help'

# 최초 계산 검증: 지정 게임 ID만 처리
./gradlew recommendationPrecompute --args='--game-ids=10,20,30 --mode=INITIAL_LOAD'

# 전체 최초 계산: 모든 기존 게임을 후보 모집단으로 사용
./gradlew recommendationPrecompute --args='--all --mode=INITIAL_LOAD'

# 일반 갱신: 준비 완료된 게임만 후보로 사용
./gradlew recommendationPrecompute --args='--all --mode=REFRESH'

# 실패한 ID만 재처리: 실패한 실행과 같은 모드 사용
./gradlew recommendationPrecompute --args='--game-ids=10,30 --mode=REFRESH'
```

`--all`과 `--game-ids` 중 하나 및 `--mode`를 반드시 지정한다. 지정 ID는 중복 제거 후 오름차순 처리한다. 전체 실행은 시작 시 최대 게임 ID를 고정하고 100개씩 조회하며, 실행 도중 추가된 게임은 다음 실행 대상으로 남긴다.

## 전체 실행의 공통 계산 재사용

- 전체 실행은 시작 시 장르, 공통 적격 후보, 평가 통계와 행동 점수가 필요한 기준 게임을 읽기 트랜잭션에서 준비한다.
- 사용자 행동 점수가 없는 게임은 같은 전체 장르 집합별 기본 순위를 재사용한다. 그룹별 상위 21개에서 기준 게임 자신을 제외하고 최대 20개를 저장한다.
- 장르 정보가 없는 게임은 정상적인 빈 결과로 처리한다. 행동 데이터가 있는 기준 게임은 기존 추천 쿼리를 사용한다.
- 기본 추천은 실행 시작 시 준비한 데이터를 기준으로 계산하고, 행동 기준 게임의 기존 쿼리는 실행 시점 데이터를 사용한다. 실행 중 원본 변경을 모든 게임에 즉시 반영하는 구조는 아니다.
- 지정 ID 실행은 작은 범위의 검증·재처리를 위해 기존 개별 계산을 유지한다.
- 로그에서 공통 데이터 준비 시간과 장르 조합별 계산 횟수를 확인할 수 있다. 이 계산 시간과 전체 저장 완료 시간은 구분해야 한다.

## 후보 배치 저장

- 게임 하나의 후보 최대 20개는 JDBC 다중 행 INSERT 한 번으로 저장한다. 드라이버의 배치 재작성 옵션을 별도로 설정할 필요는 없다.
- 기존 후보 삭제, 새 후보 INSERT, 계산 성공 상태 변경은 같은 게임의 트랜잭션으로 처리한다. JDBC 저장과 JPA 상태 변경 중 어느 쪽에서 실패해도 전체 교체가 롤백된다.
- 여러 게임을 한 트랜잭션으로 묶지 않으므로 성공한 게임은 즉시 반영되고 다른 게임의 실패에 영향을 받지 않는다.
- 2026-10-21 로컬 MySQL에서 후보 20개 교체를 방식별 200회 측정했다. 워밍업 후 순서를 바꿔 비교했을 때 기존 저장 1,851ms, 다중 행 INSERT 785ms였다. 모든 트랜잭션은 롤백했고 기존 후보 10,140행은 유지했다. 커밋 비용·전체 실행 시간을 포함한 성능 결과는 아니다.

## 결과와 중복 실행

- 100건마다 진행 상황, 종료 시 처리·성공·실패 건수, 실패 ID, 소요 시간을 출력한다.
- 개별 게임 실패는 기존 정상 결과를 유지하고 다음 게임을 처리한다. 실패 ID는 같은 모드의 지정 ID 명령으로 재실행한다.
- 같은 MySQL 서버의 같은 DB에 대한 계산은 별도 터미널에서도 하나만 실행된다. DB별 이름의 `GET_LOCK`을 전용 연결에서 유지하고 종료 시 해제한다. 실제 연결이 종료되면 MySQL이 잠금을 해제하며, 잠금 연결 확인 실패 시 실행을 중단한다.
- 종료 코드: `0` 정상 완료, `1` 개별 실패 또는 실행 오류, `2` 다른 계산 실행 중. Gradle은 0이 아닌 종료 코드를 작업 실패로 표시한다.
- 추천 조회는 계속 가능하다. 이 명령은 로컬 사전 계산 테이블을 변경하지만, API의 사전 계산 조회 전환이나 전체 준비 완료 판정은 수행하지 않는다.

## 상세 연관 추천 조회 전환

- 대상은 `GET /api/v1/games/{gameId}/related`이다. 맞춤 추천은 아래의 별도 설정으로 전환한다.
- `recommendation.related.precomputed-enabled`의 기본값은 `false`이며 기존 추천 쿼리를 유지한다.
- 전체 최초 계산의 완료·실패 여부를 확인한 뒤, 백엔드 실행 환경변수 `RECOMMENDATION_RELATED_PRECOMPUTED_ENABLED=true`를 지정하고 백엔드를 재시작하여 전환한다. IntelliJ 실행 시에는 Spring Boot 실행 구성에 지정한다. 이미 실행 중인 백엔드에 터미널의 `export`가 반영되지는 않는다.
- 활성화하면 마지막 성공 시각이 있는 기준 게임은 저장된 순위대로 최대 5개를 반환한다. 점수는 저장 값을 사용하고 게임명·이미지·IGDB 평점·장르 정보는 현재 데이터를 조회한다. 후보 자격과 순위는 요청마다 재계산하지 않는다.
- 정상 계산된 빈 목록은 그대로 반환하며, 재갱신 중이거나 실패했어도 이전 성공 결과를 사용한다. 마지막 성공 이력이 없는 게임은 기존 쿼리로 계산한다. 신규 게임의 준비 완료 기반 공개 제한은 후속 단계에서 적용한다.
- 존재하지 않는 게임의 오류와 응답 형식은 유지한다. 기존 방식으로 되돌리려면 설정을 `false`로 변경하고 백엔드를 재시작한다. 저장된 후보는 삭제하지 않는다.

## 맞춤 추천 조회 전환

- 대상은 `GET /api/v1/games/recommendations/personalized`이다. `recommendation.personalized.precomputed-enabled` 기본값은 `false`이며 기존 계산을 유지한다.
- 전체 최초 계산 완료를 확인한 뒤 백엔드 실행 환경변수 `RECOMMENDATION_PERSONALIZED_PRECOMPUTED_ENABLED=true`를 지정하고 재시작한다. 상세 추천 전환 설정과 독립적으로 켜고 끌 수 있다.
- 기록 기반 및 온보딩 선호 게임 기반 경로에서 기준 게임들의 저장 후보를 일괄 조회한다. 마지막 성공 이력이 있는 기준 게임만 저장 결과를 사용하며, 재갱신 중·실패 시에도 이전 성공 결과를 활용한다.
- 사용자 기록 게임과 온보딩 경로의 선호 게임을 요청 시 제외한다. 남은 후보를 저장 순위 순서로 다시 1~5위로 매겨 `20, 17, 14, 11, 8`점을 부여한다.
- 제외 후 5개 미만이거나 성공 이력이 없는 기준 게임은 해당 ID들만 묶어 기존 쿼리를 실행한다. 그 기준 게임의 후보 목록 전체를 교체하여 저장 후보와 중복 합산하지 않는다. 실제 적격 후보가 5개 미만이면 그 수만 사용한다.
- 최종 점수는 기존처럼 기준 게임별 순위 점수 합 + 사용자별 장르 가산점 + 후보 IGDB 평점 × 0.5이다. 저장된 연관 점수를 직접 더하지 않는다. 온보딩 장르 전용 경로와 최종 동점 정렬도 유지한다.
- 사용자별 최종 추천 결과는 저장하지 않는다. 보충 쿼리의 실행 빈도와 API 지연 시간은 별도 성능 검증에서 확인한다. 신규 미준비 게임의 공개 제한은 후속 단계에서 적용한다.
